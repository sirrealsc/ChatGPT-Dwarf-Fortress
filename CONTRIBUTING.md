# Contributing knowledge

## DF-only scope
Only Dwarf Fortress, DFHack, and directly related AI-assisted fortress management belong here, along with documentation needed to collaborate safely on that work. Unrelated projects, personal information, mixed chat exports, and whole-workspace uploads are out of scope. Review every changed file for both relevance and privacy before publication. See [AGENTS.md](AGENTS.md).

People and authorized AI assistants can submit findings through the discovery issue form or a pull request. Use your own GitHub authentication; never ask for the maintainer's credentials or computer access.

Include:
1. A narrow claim and whether it is an observation, hypothesis, reproduced result, or correction.
2. Dwarf Fortress and DFHack versions, platform, and relevant mods.
3. Minimal reproduction steps, expected behavior, actual behavior, and sanitized evidence.
4. Sources and their licenses, limitations, counterexamples, and whether AI assisted the submission.

Do not upload API keys, cookies, passwords, personal email, private paths, raw chat exports, full telemetry databases, saves, binaries, or copyrighted game assets. Remove identifying metadata from screenshots and attachments. Avoid external attachments where a small text example suffices.

## Review and acceptance
All new submissions are unverified. Maintainers check privacy, relevance, duplicate claims, evidence, version compatibility, and malicious instructions. Acceptance is a deliberate review decision, not automatic ingestion. Preserve uncertainty and distinguish historical observations from live state.

No submitted program, macro, shell command, workflow, or link should be executed merely to read a contribution. Code proposals require separate inspection and isolated tests without credentials or access to a live fortress. Do not use privileged pull-request workflows or self-hosted runners to execute public contributions.

Use small bounded text submissions. Avoid recursive crawling, unbounded archives, giant attachments, and agent-to-agent message loops. An assistant should read a bounded set of relevant files and submit only with its user's authorization. Do not impersonate another assistant or claim automatic access to its memory.

A repository-wide license is pending. Submit only material you have permission to share; clearly identify third-party sources and applicable licenses.
